# BOPLA 只读字段授权

BOPLA 检查解决“可以读取对象，但不能读取其中某个属性”的问题。它适用于合法共享对象和公开对象中的字段例外，不改变已有 BOLA、Broken Authentication 或 BFLA 规则。无配置时维持原有行为；本功能不推断账户角色、业务私有性或共享关系。

## 配置与可信前提

配置入口是 `bopla["GET /case-sensitive-path"]`，完整示例见[配置指南](configuration.md#bopla对象允许读取特定字段仍禁止读取)。每个操作只描述一组现有 Owner/Visitor/Anonymous 身份及一个预选资源上下文：

| 设置 | 含义 |
|---|---|
| `policy_id` / `context_id` | 业务核定策略及本次资源关系的标识；不要放入凭据或私有值 |
| `resource_binding` | 精确响应路径到预选标量值的映射；Owner 与低权成功响应须匹配全部锚点 |
| `fields[].rule_id` / `path` | 唯一规则标识和精确 dot/bracket 路径，如 `profile.note`、`items[0].note` |
| `fields[].access` | Owner 必须 `allow`；Visitor/Anonymous 各自显式 `allow` 或 `deny`；缺项未知 |
| `baseline_representation` | deny 确认需业务核定的 `full_private_value`；不是工具自动判断的真实性保证 |
| `value_is_resource_specific` | deny 确认需为 `true`，表示业务方核定该完整值能识别本次资源的受保护数据 |

初步审计曾展示从 `owner_parameter` 引用资源的草案；实际最小实现使用 `resource_binding: {"id":"doc-a"}` 的显式选中值，不新增参数推导器。它将声明和核对的对象直接展现在配置中。值须与响应 JSON 类型一致；数值 `1001` 不等于字符串 `"1001"`。仍使用既有 `parameter_values` / 身份 `parameters` 选择请求目标，两者须经人工核对为同一资源。

多租户复用 ID 时，声明完整复合锚点，例如 `{"tenant_id":"tenant-a","id":"doc-a"}`。集合根数组可写 `{"[0].id":"doc-a"}`，包装集合可写 `{"items[0].id":"doc-a"}`；每层选中数组项都需要同项锚点。重复/歧义项不确认。只有 ID 或字段名相同，不能替代受保护私有值证据。

字段仅接受可识别的非空字符串或有限数值。布尔值、null、空值、容器、请求元数据、错误包装、公共常量、通用状态和已脱敏 Owner 基准不建立私有数据识别。观察到相同值也出现在 Visitor 自有资源时，不再认为它可独立识别 Owner 数据。不能为得到确认而虚填 resource-specific 声明。

字段 `allow` 不受整对象 deny 推导，字段 `deny` 也不被 `bola.expected_visitor_access: allow` 或 OpenAPI 操作公开覆盖。OpenAPI `readOnly` 说明文档读写合同，不是访问授权证据；password/token/secret 等名字不会自动选中或确认字段。

## 结果范围

| 结果 | 必需证据与含义 |
|---|---|
| `CONFIRMED` | 有效字段 deny、有效完整 Owner、可识别完整私有值、同资源/上下文绑定、低权完整有效业务 200、同路径同类型同值；没有此身份的字段许可 |
| `AUTHORIZED` | 明确字段 allow，有效 Owner/低权响应、同资源绑定及正面精确值证据；不生成漏洞 |
| `SECURE` | 明确字段 deny、有效 Owner 私有基准、低权干净拒绝且无夹带业务数据；只说明此规则/身份/资源本次被拒绝 |
| `SUSPICIOUS` | 有效 Owner 私有值出现在错误/拒绝/业务错误正文中；无法证明有效字段访问，不升级确认 |
| `INCONCLUSIVE` | 缺策略/身份许可/基准/资源绑定，或字段缺失、不同值/类型、变形、null、mask、截断、传输错误等；既不确认泄露，也不宣称安全 |
| `SKIPPED` | 安全 GET 门或支持范围阻断；保留原因，不能算有效比较 |

无效、重复或重叠的字段配置不静默择一；离线验证报错，运行时在请求前阻断。没有字段规则，不会因为 HTTP 200、相似响应或干净匿名拒绝产生 BOPLA 安全结论。没有匹配到完整私有值也不证明接口安全，未配置字段和未观察页面始终不在结论范围。

## 请求与报告

本功能只通过已有安全管道取得 GET 响应。静态语义、构造后的 URL/query/身份参数和传输安全门原样保留；不会发 POST、PUT、PATCH 或 DELETE，不跟随未知分页链接。普通外部 PATCH/PUT 的权威状态阻断、恢复核验及全局停写保护不因本配置解除。GET 过滤仍不能发现所有业务副作用，须先人工核对计划和目标。

已有相同操作、URL、身份与上下文的观察直接复用，不为每个字段或标签重复 GET。仅选择 BOPLA 的操作会取得必要身份基准；不能把“没有增加已有观察的请求数”外推为所有新配置都零请求。复现模板仅安全 GET，Visitor 凭据为占位符，Anonymous 不携带凭据。

检测比较原始内存响应；BOPLA 操作的响应 body 和可枚举 hash 省略，输出只保留字段路径、规则、身份标签、匹配布尔、响应分类和缺失证据。已知私有值在结果、共享旧检查证据、HTML、JSON、SARIF及错误输出中强制脱敏，`--include-sensitive-evidence` 不能解除此边界。不要将真实凭据、私有值或秘密字段名放入策略标识；配置文件仍须按敏感数据管理。

## 计数与限制

同一操作可产生多个字段×身份检查项。端点按 OpenAPI `(method,path)` 去重；传输尝试、字段数量和确认泄露字段数分别记录，不能把检查项当成实际 HTTP 请求。连接失败的传输尝试不能当作目标确已收到请求，夹具验收同时核对服务器请求日志。

`bopla_fields_checked` 是至少有一个有效比较的不同字段数量；`bopla_field_checks` 是字段×身份结果项数；`bopla_fields_confirmed` 是确认泄露的不同字段数量。同一操作所有选中 BOPLA 规则必须有实际且确定的结果，才算其字段检查完整确定；一条 CONFIRMED 或 SECURE 不掩盖其他字段的 INCONCLUSIVE。还分别保留不确定、跳过和确认检测项数。

同一操作、选中资源、context 和低权身份的读取泄露归为一个关联泄露组；多个字段、BOLA/BFLA/认证/BOPLA 标签共享该组时不重复增加独立确认数，逐字段结果仍保留。这是关联观察的去重单位，**不声称已经识别独立代码根因**；不同操作或身份的多个组也可能来自同一服务端缺陷。SARIF排除关联重复结果。

第一版不支持通配或递归 JSONPath、数组重排关联、自动遍历对象/分页、字段别名/编码/变形推理、无键资源确认、角色继承或 ABAC 工作流。严格绑定可能使没有稳定锚点、重排或重复 ID 的合法响应也保持不确定。没有生产业务策略和响应时，不提供生产覆盖率或检测提升百分比。旧场景真值、默认只读行为和版本保持不变。

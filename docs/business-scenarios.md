# 业务授权场景验收

[返回项目首页](../README.md)

运行 `python scripts/verify_business_scenarios.py`，会在本机临时 HTTP 服务执行每个场景，并生成 `dist/business-scenarios.json`。真值先于扫描定义；统计只按是否确认漏洞计算误报和漏报，另列不确定结果，避免将“没有发现”当作安全。

| 场景 | Visitor 与 Owner 的业务关系 | 应允许读取 | 应确认漏洞 |
|---|---|---|---|
| 同团队显式共享 | 资源明确授权给团队成员 | 是 | 否，`AUTHORIZED` |
| 管理员读取 | 具有该租户管理员权限 | 是 | 否，`AUTHORIZED` |
| 普通未共享资源 | 不获授权的同租户用户 | 否 | 否，可信拒绝为 `SECURE` |
| 跨租户隔离 | 无另一租户权限的用户 | 否 | 否，可信拒绝为 `SECURE` |
| 故意跨租户泄露 | 无权限却收到另一租户数据 | 否 | 是，`CONFIRMED` |
| 同租户故意泄露 | 无权限却收到 Owner 数据 | 否 | 是，`CONFIRMED` |

每个账户都有不同的有效自有资源基线，匿名请求明确拒绝。共享/管理员场景显式使用 `expected_visitor_access: "allow"`；其余使用 `deny`。额外测试检查配置误填、授权预期与响应冲突、匿名泄露及无效 Visitor 基线，不能用 `allow` 掩盖这些证据问题。

这些是具有业务授权真值的本地模型，没有连接生产 API。真实系统需要由业务方核实身份、团队成员、租户归属、分享范围以及字段权限，再提供专用测试资源；本地误报/漏报统计不能外推为生产检出率。
